# 01 · 基础设施：util.py 与 http.py

这两个文件不包含任何业务判断，但决定了「整套东西是不是可复现、是不是扛得住坏网络」。

---

# 一、`util.py`（94 行）— 小工具

## 为什么单独一个文件

时间、比例、文本裁剪被 4 个模块用到。如果散落各处，就会出现「三个地方用三种时间格式」的经典烂摊子。
这里的原则是：**只放纯函数，不 import 业务模块，不碰网络**。

## 逐个说明

### `utcnow()` · 第 16 行

```python
return _dt.datetime.now(_dt.timezone.utc).replace(tzinfo=None)
```

返回**不带时区的 UTC 时间**。

- 为什么不用 `datetime.now()`：本机是 UTC+8，本地时间会让「3 天前」这种判断在时区里漂。
- 为什么要 `.replace(tzinfo=None)`：GitHub 返回的是 `2026-08-16T01:36:11Z`，解析后也是 naive。
  全项目统一用 naive UTC，比较时不会踩 `can't compare offset-naive and offset-aware` 的坑。

### `parse_iso(value)` · 第 21 行

用正则 `_ISO` 吃掉 `2026-08-16T01:36:11Z` / `+00:00` / 空格分隔三种写法，返回 naive datetime。
解析失败返回 `None`（**不抛异常**），因为上游数据脏是常态。

### `days_since(value, now=None)` · 第 34 行

把一个 ISO 字符串换算成「多少天前」。`value` 为空/解析失败 → 返回 `None`。
所有「最近提交多久前」的检查都走它，好处是**测试可以注入固定 now**，结果可复现。

### `age_days(created, pushed, now)` · 第 42 行

仓库年龄，**下限 1.0**。为什么要下限：`_cadence` 里要算「每月提交数 = commits / (age/30)`，
新仓库 age 可能是 0，会除零。

### `human_days(days)` · 第 49 行

`3 天前` / `4 个月前` / `1.2 年前`。报告里给人看的，不要出现 `76.0000001`。

### `clamp(value, 0, 1)` · 第 61 行

所有检查的 `pct` 出去前都夹到 `[0,1]`，防止某个分支手滑返回 1.2 把总分顶过 100。

### `ratio(hit, total, empty=0.5)` · 第 65 行

安全的 `hit/total`。关键在 `empty` 参数：**当“没有东西可算”时给 0.5 而不是 0**
（例如宣称数为 0 时，不能说“可验证比例是 0%”，那是误判）。

### `squish(text, limit)` · 第 72 行

压空白 + 截断 + 加省略号。拼 evidence 字符串时用。

### `dedupe(items, key)` · 第 82 行

保序去重。红旗和清单都要去重（同一个原因可能被两条检查同时报出来）。

# 二、`http.py`（215 行）— 唯一网络出口

## 为什么要自己封装

如果直接用 `urllib` 到处写，会立刻遇到四个问题：

1. **GitHub 匿名配额 60 次/小时** —— 反复调试几轮就没了；
2. **网络抖** —— 一次 `ConnectionResetError` 就让整个报告失败；
3. **错误语义** —— 404（不存在）和 403（限流）要对用户说完全不同的话；
4. **GBK 控制台** —— 中文报告打出来是乱码。

这四件事都在这一层解决，上层（sources）只管调 `http.get_json()`。

## 错误类型（第 32–46 行）

```python
class FetchError(Exception)      # 所有网络失败
class NotFound(FetchError)       # 404：仓库名拼错 / 已删除 / 转私有
class RateLimited(FetchError)    # 403 且 x-ratelimit-remaining == 0
```

`RateLimited` 带 `reset_epoch`，`_until()`（第 178 行）把它换算成「N 分钟后恢复」——
报告里能直接告诉用户“等 12 分钟”而不是干巴巴一句 403。

## 缓存（第 48–84 行）

```python
cache_dir()            # %LOCALAPPDATA%\claimaudit（可用 CLAIMAUDIT_CACHE 覆盖）
_cache_file(url, extra) # sha1(url + accept + token 标记)
_read_cache(path, ttl)  # 过期就返回 None
_write_cache(...)       # 写失败静默（只读家目录不能把审计搞崩）
```

设计取舍：

- **按 URL 缓存，不按仓库缓存**——每条 API 各自的 TTL 更精确；
- **`extra` 里带 accept 和“是否带 token”**——同一个 URL 带不同 Accept 头返回内容不同，混用会串味；
- **默认 TTL 1800 秒**：够跑完一轮调试，又不至于让你看昨天的数据；
- **`--no-cache`**：怀疑缓存脏时用（写入磁盘失败时也可能命中旧值）。

## `get()`（第 99 行）— 唯一的请求函数

流程：

1. 先查缓存 → 命中直接返回 `(body, headers)`
2. 组 header：UA（写明是谁）、Accept、`Authorization: Bearer`
3. `_open()` 发请求
4. **HTTPError 分诊**：
   - 404 → `NotFound`
   - 403/429 且 `x-ratelimit-remaining == 0` → `RateLimited`（带 reset）
   - 其它 → `FetchError`（带上状态码和原因）
5. `URLError` / `TimeoutError` → 统一包装成 `FetchError`

返回值一律是 `(文本, 小写化的 headers 字典)`。**为什么 headers 要小写**：
调用方写 `headers.get("link")` 就行，不用记 GitHub 到底返回 `Link` 还是 `link`。

## `_open()`（第 86 行）— SSL 降级

```python
try:
    return urllib.request.urlopen(request, timeout=timeout)
except ssl.SSLError:
    # 记录 warning，用不校验证书的 context 重试一次
```

为什么要这段：企业网/校园网的中间人证书会让 Python 直接报证书错误，
而用户的真实诉求是“帮我把这个仓库看了”，不是“帮我检查 TLS”。

代价是**必须诚实**：降级时往 `http.warnings` 里塞一句话，
`cli.run()` 会把它并入报告的「采集备注」，读者能看到“这条通道不可信”。

## `get_json()`（第 156 行）

包一层 `json.loads`，解析失败时报「返回的不是 JSON（可能是镜像/登录墙）」——
这句话救过很多次，因为公司网关拦下来时返回的是一整页 HTML。

## `ensure_utf8_stdout()`（第 205 行）

Windows 控制台默认 cp936，报告里有 `█ ░ ✅` 和中文，不重配编码会 `UnicodeEncodeError`。
在 `cli.run()` 一开始调用。

## 这一层的坑（都踩过）

| 坑 | 现象 | 现在的处理 |
|---|---|---|
| GitHub 匿名 60/h | 调几轮就 403 | 缓存 + `--token` 提高上限 |
| 空仓库写操作 | `409 Git Repository is empty` | 与读无关，但发布脚本里踩过（见 `07-设计决策.md`） |
| 网络重置 | `WinError 10054` | 上层可重试；`http.get` 本身不重试（避免审计变慢） |
| gzip | urllib 不自动解压 | 干脆不发 `Accept-Encoding` |
| 大仓库 tree 截断 | `truncated: true` | 目前接受：只统计拿到的部分，不谎称全量 |
