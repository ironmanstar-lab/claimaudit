# 03 · 宣称抽取：claims.py（197 行）

这一层最容易写爽、也最容易翻车。它的任务只有一个：

> 从一堆 Markdown/网页文本里，找出**作者在对读者许诺什么**。

---

## 为什么是正则，不是 LLM

| | LLM 抽取 | 正则抽取 |
|---|---|---|
| 每次运行结果 | 可能不同 | 完全一致 |
| 成本 | 要 Key、要钱 | 0 |
| 离线 | 不行 | 行 |
| 可解释 | 要问它为什么 | 命中的是哪个词，一目了然 |

报告里的每一行「它说…」都要能被读者指着说“这句确实在吹”，
所以**可复现**比“更聪明”重要。LLM 可以在这个结果之上做解读（见 `SKILL.md`），
但不能替代这一层。

## 1. `RULES` · 第 15 行 — 八类宣称

每行是 `(kind, severity, 正则, 怎么核)`：

| kind | severity | 抓什么 | 举例 | 怎么核 |
|---|---:|---|---|---|
| `money` | 3 | 收益/致富 | 月入、年化、翻倍、回本、ROI | 要净值曲线、样本期、最大回撤 |
| `absolute` | 3 | 绝对化 | 唯一能…、最强、零风险、100% | 要对照基线与失败案例 |
| `quantity` | 1 | 数量 | 123+ 因子、12 个技能 | 数一遍实际条目 |
| `effortless` | 2 | 轻松上手 | 一键、零基础、开箱即用 | 看依赖数、要不要买 Key |
| `free_open` | 2 | 开源/免费 | 开源、免费、白嫖 | 核对 LICENSE 与是否留后门 |
| `time` | 2 | 时间承诺 | 3 分钟上手、7 天回本 | 要可复现的计时样本 |
| `authority` | 1 | 身份背书 | 大厂、前阿里、CTO | 身份无法核实，只看产出 |
| `social` | 2 | 社会证明 | 全网首发、官方推荐 | 去官方渠道核对 |

### 词表为什么这么写（几个具体的教训）

**`收益率?` → `收益率`**
原来的 `收益率?` 会匹配到「收**益**」两个字，于是
“宣称开源却没有 LICENSE，或**收益**宣称却没有免责声明 → 最高 C”
这句**规则说明本身**被判成了收益承诺。模式收窄后消失。

**`唯一.{0,8}(能|可|方法|选择…)`**
裸的 `唯一` 会命中“cache.py 唯一读取接口”这种**技术表述**。
收紧成“唯一 + 能力动词”才抓得住真正的吹法。

**`\bcto\b`**
原来写 `cto`，结果 `fa**cto**r-mining` 被当成“CTO 背书”。加词边界解决。

**中文没有词边界**
所以中文模式只能靠“足够长的具体短语”，英文才敢用 `\b`。

## 2. `Claim` · 第 32 行 — 一条宣称长什么样

```python
@dataclass
class Claim:
    kind: str        # 上面八类之一
    text: str        # 原文那一行（清洗过的）
    severity: int    # 1~3，决定在报告里的排序
    verifiable: bool # 有没有可核口径
    hint: str        # 怎么核（写给人看的一句话）
```

`as_dict()` 让 `--json` 直接吐出去，agent 可以拿去二次处理。

## 3. `extract()` · 第 133 行 — 主流程

```
for 每条规则:
    for 每个命中:
        per_kind 上限到了 → 换下一类
        命中在表格里 / 代码块里   → 跳过   (_is_table_or_code)
        命中在“规则说明”行里       → 跳过   (_is_meta_line)
        取这一行做上下文           → _line_around
        上下文像标题/导航          → 跳过   (_looks_like_headline)
        去重 → 记录
按 severity 降序、长度升序排 → 截断到 limit
```

### 四道过滤器，各自挡什么

**① `_is_table_or_code`（第 114 行）**
- 表格行（`|` 出现 ≥2 次）：因子表、参数表，全是技术内容；
- 目录行（`·` 出现 ≥3 次）：`a · b · c` 这种导航；
- 代码块内（``` 计数为奇数）：shell/python 片段。

不挡的话，报告里会出现「`\\| data/ \\| 数据获取…`」这种半截表格，非常难看。

**② `_is_meta_line`（第 88 行）**
行内出现 `例如/比如/示例/检测/识别/钩子/红线/判据/不能做`，或形如“…… → 最高 C”的，
判定为**说明性文字**，不是宣称。

这一条是被自己坑出来的：README 里描述“什么样算红旗”，
结果这些描述自己被当成了红旗。

**③ `_looks_like_headline`（第 103 行）**
≤46 字、无中文标点、带 `！？…` 或 ≤16 字 → 当标题处理。
挡的是网页侧栏/相关阅读的标题（“钉钉真勇！率先接入…”这种）。

**④ `per_kind=4`**
同一个人可以把“一键”说 20 遍。每类最多留 4 条，防止一类刷满整个表格。

### `_line_around()` · 第 53 行 — 为什么要“行”而不是“前后 28 字”

早期版本用 `text[start-28 : end+28]` 截片段，结果：

- 表格被从中间切断（`…| factors/ | 因子引`）；
- Markdown 链接残留（`…](docs/资产盘点.md) · [架构说明…`）；
- 一句话被截成两半，读起来莫名其妙。

改成“取命中所在的整行”，并清洗：
`#` 标题符号 → 列表符号 → 序号 → **Markdown 链接转成纯文本** → 去反引号/加粗/表格竖线 → 压空白。
超过 110 字才围绕命中点裁剪。

效果：报告里引用的每一句，都像人话。

## 4. `_is_verifiable()` · 第 126 行

判断“这条宣称有没有可核口径”，两个条件任一成立：

1. 带数字+单位（`%|倍|万|亿|个|条|项|分钟|小时|天|周|月|元|star`）；
2. 提到可核对象（`github|release|benchmark|数据集|代码|license`）。

这个布尔值直接决定 `_claim_numbers` 这条检查的得分——
**“说得很响但一个数字都没有”是最典型的信号**。

## 6. 已知局限（诚实写在这里）

| 局限 | 例子 | 为什么暂时不改 |
|---|---|---|
| 反讽/否定读不懂 | “别信‘月入三万’这种鬼话” 会被抓成 money | 需要句法分析，收益不抵成本 |
| 多语言 | 只有中英 | 目标受众决定 |
| 词表偏向技术圈 | “割韭菜”这类口语抓不全 | 可以在 `RULES` 里加，不需要改逻辑 |
| 上下文只有一行 | 跨行的论证抓不到 | 再扩就要做分句/分块，先记着 |

如果要扩，**只加 `RULES` 里的行**，别动 `extract` 的流程——这是这一层唯一稳定的部分。
