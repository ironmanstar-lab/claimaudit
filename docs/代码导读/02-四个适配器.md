# 02 · 四个适配器：把「目标」变成 facts

统一职责：**只取数，不评价**。四个文件都返回同一个 payload 结构（见 `00-总览.md`）。

---

# 一、`sources/github.py`（230 行）

## 1. `parse_target()` · 第 39 行

接受四种写法，统一成 `owner/repo`：

```python
git@github.com:psf/requests.git          → psf/requests   (# _SCP)
https://github.com/psf/requests/tree/main → psf/requests   (# _HTTP, 截到第二段)
https://github.com/psf/requests.git       → psf/requests   (# 去掉 .git)
psf/requests                              → psf/requests   (# _SLUG)
```

为什么值得单独写：用户从浏览器地址栏、README、`git clone` 命令里复制来的格式各不相同，
一个函数吃掉差异，`cli.load_payload()` 才能一行判断“这是不是仓库”。

**坑**：`_SLUG` 会把 `docs/report.md` 也认成 `owner/repo`。
所以 `cli` 里先判断「本地文件存在吗」，再判断 slug（顺序很关键）。

## 2. `_signals(paths)` · 第 86 行 — 从文件树读“卫生程度”

输入是**全部文件路径**，输出一组布尔/计数：

| 字段 | 判定方式 | 代表什么 |
|---|---|---|
| `has_tests` | `tests/`、`*_test.py`、`*.test.js` | 有没有自动化验证 |
| `has_ci` | `.github/workflows/`、`.gitlab-ci.yml`… | 有没有持续集成 |
| `has_license_file` | 根目录有 `LICENSE`/`COPYING` | 法律上能不能用 |
| `committed_node_modules` | 有 `node_modules/` 路径 | 把依赖提交进仓库 = 不可审计 |
| `binaries` | `.exe/.zip/.whl/.msi` 等 | 闭源交付 |
| `has_demo_data` | 路径含 `demo/fixture/sample/synthetic` | 能不能离线复现 |
| `dependency_files` | requirements/pyproject/package.json… | 装起来要几步 |
| `docs_count` / `code_files` | 后缀计数 | 文档与代码体量 |

这是**唯一廉价且难造假**的证据源：README 可以吹，文件树不会。

## 3. `probe()` · 第 131 行 — 6 个请求，全部容错

```python
repo      = GET /repos/{slug}                       # 必需，失败就退出
commits   = GET /repos/{slug}/commits?per_page=1    # 用 Link 头算总数
contrib     = GET /repos/{slug}/contributors         # bus factor
readme    = GET /repos/{slug}/readme  (raw)          # 宣称的主要来源
tree      = GET /repos/{slug}/git/trees/{branch}     # 文件树（recursive）
releases  = GET /repos/{slug}/releases              # 仅 --deep
```

设计要点：

- **只有 `/repos` 是必需的**，其余全部 `try/except`，失败只往 `notes` 里写一句。
  半个事实也比整个报告报错有用；
- **提交数不拉全部**：`?per_page=1` 然后读 `Link: <...?page=340>; rel="last"`，1 次请求拿到 340；
  没有 Link 头（提交很少）时退回 `len(data)`（`_count_from_link`，第 78 行）；
- **README 用 raw Accept**：`Accept: application/vnd.github.raw` 直接拿 Markdown 原文，
  不用 base64 解，也不用猜编码；
- **`facts["age_days"]` 和 `days_since_push` 在这里算好**，rubric 直接用（也可用 `now` 重算，测试更稳）。

## 4. 坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 大仓库 tree 被截断 | `truncated: true`，文件数偏少 | 接受，不谎称全量 |
| 空仓库 | 某些端点 409 | 读操作里少见；发布脚本里踩过 |
| 403 vs 404 | 私有/无权限都可能是 404 | 文案写「不存在（404）—— 拼错、已删除或已转私有」 |
| 贡献者接口对大仓库慢 | 超时 | 失败就跳过，`bus_factor` 检查自动失效 |

# 二、`sources/web.py`（144 行）— 网页正文提取

## 为什么不用第三方解析库

零依赖是硬约束（用户不装任何东西就能跑）。`html.parser` 够用，因为**我们只要正文文本**，
不要 DOM 树。

## `_Extractor` 状态机（第 18 行）

跟踪四样东西：`_skip`（在 script/style 里）、`_in_para`（在 `<p>/<article>` 里）、
`_in_a`（在链接里）、`_heading`（在标题里）。

### 四个刻意的取舍

**① 丢掉 `<a>` 里的文字**（第 80 行）

```python
if self._skip or self._in_a:
    return
```

原因：新闻站的「相关阅读」「推荐位」全是链接，它们的标题长得像宣称。
早期版本把别人文章的标题当成了本文的宣称，报告里全是无关的句子。
**代价**：正文里带链接的句子会被截断——可接受。

**② 只保留长段落**（第 97–110 行）

```python
long_paras = [p for p in parser.paragraphs if len(p) >= 60]
if len(parser.paragraphs) >= 3:
    text = "\n".join(long_paras or parser.paragraphs)
```

超过 60 字才算正文段落；一个页面如果连 3 个段落都没有，退回全文。
这样导航栏、按钮文字、面包屑基本进不来。

**③ 遇到脚本/样式直接跳过**（`_SKIP_TAGS`，第 14 行）
否则 JS 字符串会被当正文。

**④ 记录 promo 线索**（`PROMO_HINTS`，第 10 行）
加群/网盘/私域/名额…这些词命中就记进 `facts["promo_hits"]`，
后续 `_promo` 检查会用到。

## `_numbers()` · 第 104 行

把页面里的数字串抓出来（带单位）。目前只作参考，不参与打分——
因为「有数字」不等于「数字可信」，真正的判定在 `_claim_numbers` 里按“宣称是否带口径”来算。

# 三、`sources/video.py`（100 行）— 诚实地说“我核不了”

这是全项目最“反直觉”的适配器：它**故意不评分**。

## `detect()` · 第 31 行

按域名判断平台：抖音/B站/小红书/快手/YouTube/公众号。

## `_video_id()` · 第 39 行

正则从 URL 里抠 ID（`/video/BV1xx…`、`?v=xxx`、`youtu.be/xxx`）。目前只用于展示。

## `probe()` · 第 54 行

- 有 `transcript` → 拿文案当正文，正常评分；
- 没有 → 只抓页面 `<title>` 和作者，然后**标记 `transcript_required = True`**。

这个标记在 `rubric._insufficient()` 里会让整份报告变成「未定级」：

> 视频没有字幕/文案：口播里的承诺一条都没法核

**为什么不给个大概分**：口播是短视频安利的主要载体，没有它，
任何分数都只是根据标题瞎猜。工具的价值在于**说清证据缺口**，不在于总有话说。

# 四、`sources/textfile.py`（38 行）— 本地文案

- `looks_like_text()`：后缀白名单（md/txt/srt/vtt/html）；
- `probe()`：读文件 → 提取标题行、正文、URL。

用途：把视频字幕、公众号原文、商品页另存为文件后审计。
也是**离线复现**的基础（配合 `--offline`）。

---

## 四者的共同约束

1. **都能失败得体面**：抛 `FetchError` 家族，由 CLI 统一转成退出码 2；
2. **都不算分**：分数只在 `rubric.py` 里产生；
3. **都写 `notes`**：取不到的字段要留话，报告底部会显示「采集备注」。
