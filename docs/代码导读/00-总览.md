# 00 · 总览：这套代码到底在干什么

> 目标读者：想读懂并改动 ClaimAudit 的人（包括三个月后的你自己）。
> 每个文件都按「它解决什么问题 → 函数怎么实现 → 为什么这么写 → 坑在哪」讲。

---

## 一句话

输入一个**链接**，输出一份**能复核的尽调报告**：它宣称了什么、我们核到了什么、还差什么证据。

它**不判断真假**，只判断「有没有可核的证据、够不够」。

## 目录与职责

```
claimaudit/
├── __init__.py          版本号（0.2.0）
├── util.py              时间/比例/文本小工具，零业务逻辑
├── http.py              唯一的网络出口：缓存、重试、错误分类、SSL 降级
├── sources/             四个适配器，把「目标」变成统一的 facts 字典
│   ├── github.py        仓库：star/提交/文件树/LICENSE/README
│   ├── web.py           网页：正文段落、外链、引流词
│   ├── video.py         视频：平台/ID/标题，缺字幕时标记「无法核」
│   └── textfile.py      本地 md/txt/srt
├── claims.py            从文本里抽「宣称」：8 类词表 + 行级上下文
├── rubric.py            18 项检查 + 3 条封顶 + 1 条拒答 → 分数与等级
├── report.py            三种渲染：Markdown / JSON / 自包含 HTML
└── cli.py               参数解析、目标分发、退出码
bench/                   黄金集：7 个带期望等级的样本（迭代用）
tests/                   44 个单测
```

## 数据是怎么流动的

```
 用户输入 URL/路径
        │
        ▼
  cli.load_payload()          ← 判断这是仓库、网页、视频还是本地文件
        │
        ▼
  sources/*.probe()           ← 联网取数，产出 facts 字典 + 正文文本
        │
        ▼
  rubric.build_context()      ← 把 payload 整理成 {source,target,facts,text,claims}
        │      └─ claims.extract(text)  ← 抽宣称
        ▼
  rubric.score(ctx)           ← 18 项检查各自打分 → 加权 → 封顶 → 定级
        │
        ▼
  report.render / render_json / render_html
```

关键点：**取数（sources）和判断（rubric）彻底分开**。
前者只负责“把事实拿回来”，后者只负责“按规则算分”。
所以新增一个数据源，不需要碰评分逻辑；改评分，也不需要联网。

## 两个核心契约

### 1. 适配器的返回值（所有源统一）

```python
{
  "source": "github" | "web" | "video" | "text",
  "target": "owner/repo 或页面标题",
  "url":    "原始地址",
  "notes":  ["取数过程中的失败说明，会出现在报告底部"],
  "facts":  { ... 该源特有的事实 ... }
}
```

`facts` 的形状按源不同：

| 源 | 关键字段 |
|---|---|
| github | `stars / commits / contributors / created_at / pushed_at / license / readme{chars,text} / tree{paths,top_dirs} / signals{...}` |
| web | `title / chars / text / links / promo_hits / headings` |
| video | `platform / video_id / title / transcript / transcript_required` |
| text | `chars / text / headings / links` |

**这是整套代码的枢纽**：`rubric` 只认 `facts`，不认来源。
换源、加字段，只要 `rubric` 里对应检查读得到就行。

### 2. 检查的返回值（每条检查都必须给三样）

```python
(pct, evidence, redflag, action)
#  pct     : 0~1，这条检查满足到什么程度
#  evidence: 一句话，必须指向具体事实（文件数/日期/条数）
#  redflag : 可选，命中就进红旗区，可能触发封顶
#  action  : 可选，会变成「30 分钟自检清单」里的一步
```

返回 `None` 表示**这条检查不适用于当前目标**（比如网页没有文件树 → 跳过 `tests`），
这个权重会从分母里去掉，而不是按 0 分算（见 `04-评分引擎.md` 的“重新归一”）。

## 一次典型运行的完整链路

```bash
python -m claimaudit.cli https://github.com/owner/repo
```

1. `cli.build_parser()` 解析参数（`--json/--html/--offline/--fail-under`…）
2. `cli.load_payload()` 判断目标类型 → 调对应适配器 → 得到 payload
3. `rubric.build_context()` 取出正文，调 `claims.extract()` 抽宣称
4. `rubric.score()` 跑 18 条检查 → 加权总分 → 等级 → 封顶 → 拒答判断
5. `report.render()` 拼 Markdown；`--json` 则 `render_json()`；`--html` 则 `render_html()`
6. 退出码：0 正常 / 2 取数失败 / 3 用法错误 / 4 低于 `--fail-under`

## 三个常见改动，各自该动哪

| 想做的事 | 改哪里 |
|---|---|
| 加一条检查（比如「有没有 CHANGELOG」） | `rubric.py`：写一个 `_xxx(ctx, now)` + 在 `CHECKS` 里加一行 |
| 调权重 / 调等级线 | `rubric.py`：`CHECKS` 的权重、`GRADES` 的阈值 |
| 支持新数据源（Gitee/官方文档站） | 新建 `sources/xxx.py`，产出同样结构的 payload；`cli.load_payload()` 加一个分支 |

改完必须跑：

```bash
python -m unittest discover -s tests -t .
python bench/run.py
```

两条都绿，才算没改坏。
